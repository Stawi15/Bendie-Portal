## Implementation Strategy

**MVP scope**: Phases 1–3 (Setup, Foundational, User Story 1) deliver a working "grant access with sensible defaults" capability end-to-end — independently demoable, though a manager cannot yet fine-tune permissions until Phase 4 (US2) ships. Given US1 and US2 are both P1 and tightly coupled (an "enable-only" surface with no way to ever adjust flags is an incomplete MVP for this feature's actual purpose), the recommended real MVP checkpoint is **Phases 1–5** (through US3's authorization verification), at which point the feature is safe to expose even in a limited/internal rollout. US4–US7 (disable/reactivate, member removal, sync-safety regression, audit) complete the full spec but can each ship as independent increments after that point.
