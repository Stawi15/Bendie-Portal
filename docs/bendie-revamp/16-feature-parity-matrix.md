## Invariants that must survive any redesign

1. Every write stays scoped to the selected event or organisation (`event_id` / `organization_id`).
2. Breakout rooms: never write `agenda_sessions.breakout_rooms`. Use `save_breakout_rooms` and `choose_breakout_room`.
3. Venue time: convert through `src/lib/eventTimeZone.ts` only.
4. Planner access is decided only in `plannerAccessRules*.ts`.
5. Contacts and hidden `profiles` columns are read only through `callerProfile.ts` and `profileContacts.ts`.
6. Gallery and moderation writes run as the caller first, then fall back to the service role.
7. A Planner failure never fails a successful Portal operation.
8. Every importer keeps CSV, paste and .xlsx support with column matching.
9. The attendee app reads the same tables, so no column renames without a mobile release plan (doc 09).
